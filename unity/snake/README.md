# Snake — Unity client

Real-time multiplayer client for the `snake` game. The authoritative game
logic lives server-side in
[`packages/games/src/snake`](../../packages/games/src/snake) — this Unity
project is a renderer + input device, nothing more. It never simulates
movement, collisions, or scoring locally; it just displays whatever the
`state` messages say and sends `input` messages for arrow-key presses.

This was written without a real Unity Editor available to compile-test it —
if you hit a compile error, it's most likely a small Unity-version API
mismatch. Report it back and it'll get fixed.

## Requirements

- Unity **2022.3 LTS** or newer (2021 LTS likely works too, untested).
- WebGL Build Support module installed (Unity Hub → Installs → your version → Add Modules).
- The `com.unity.nuget.newtonsoft-json` package (Unity's own first-party
  package — not a third-party asset). Install via:
  **Window → Package Manager → "+" → Add package by name →**
  `com.unity.nuget.newtonsoft-json`

## Step 0: open this as a Unity project

Only `Assets/` exists here — no `ProjectSettings/` or `Packages/`, since
those are engine-version-specific files better generated by Unity itself
than hand-authored blind. Two ways to get a working project:

- **Unity Hub → Add → select this `unity/snake` folder directly.** Unity
  will detect the bare `Assets/` folder and generate the missing
  `ProjectSettings/`/`Packages/`/`Library/` on first open. This is the
  simplest path if your Hub version supports adopting a folder like this.
- **If that doesn't work**: create a new 3D (Built-in Render Pipeline)
  project anywhere via Unity Hub, then copy this folder's `Assets/Scripts`,
  `Assets/Editor`, and `Assets/Plugins` into the new project's `Assets/`
  folder.

Either way, install the Newtonsoft Json package (above) before opening any
of the scripts, or the Editor will show compile errors for the missing
`Newtonsoft.Json` namespace.

## One-time scene setup

The scene is built by a script rather than shipped as a hand-authored
`.unity` file (safer than hand-writing Unity's YAML format without a way to
verify it opens correctly). After opening this project in Unity:

1. **Gaming Pool → Setup Snake Scene** (menu bar). This creates the camera,
   `GameManager`/`NetworkClient`/`SnakeRenderer`/`FoodRenderer` objects, a
   UI canvas (status text, score text, game-over panel), and two prefabs
   under `Assets/Prefabs/` (`SnakeSegment.prefab`, `Food.prefab` — plain
   cube/sphere primitives, swap the materials for whatever art you want).
2. Save the scene: **File → Save As** → `Assets/Scenes/Snake.unity`.
3. Add it to Build Settings (**File → Build Settings → Add Open Scenes**).

## Testing in the Editor

With `apps/api` and `apps/game-server` running locally (`npm run dev` from
the repo root), just hit **Play** in the Editor. `GameManager` POSTs
`http://localhost:4000/matchmake/snake`, gets back `{ server, roomId }`, and
connects straight to the game-server over WebSocket — no build required to
iterate. `NetworkClient` uses `System.Net.WebSockets.ClientWebSocket` in the
Editor and only switches to the browser-bridged jslib path in an actual
WebGL build (see `Assets/Scripts/Snake/NetworkClient.cs`).

Arrow keys / WASD steer. You can't reverse directly into yourself. Hitting a
wall, yourself, or another snake ends your run — refresh (re-enter Play
mode) to join again.

## WebGL build → local CDN dev server

1. **File → Build Settings → WebGL → Switch Platform**, then **Player
   Settings**:
   - **Compression Format**: `Disabled` for the simplest local setup (the
     dev CDN server at [`scripts/serve-cdn.mjs`](../../scripts/serve-cdn.mjs)
     also transparently serves a `.br`-suffixed file with
     `Content-Encoding: br` if you'd rather test Brotli compression — set
     Compression Format to `Brotli` if so).
2. **Build**, output folder: `unity/snake/Build` (this repo's
   `unity/snake/Build/` — the dev CDN server serves straight from
   `unity/{slug}/Build/`, matching how `apps/web`'s
   [`UnityLoader.tsx`](../../apps/web/components/UnityLoader.tsx) requests
   `${NEXT_PUBLIC_CDN_URL}/snake/Build/snake.loader.js` etc). Name the build
   `snake` so the generated files are `snake.loader.js`, `snake.wasm`,
   `snake.data`, `snake.framework.js` — `UnityLoader.tsx` expects those
   exact filenames.
3. With `npm run dev` running from the repo root (starts the CDN dev server
   on `:8787` alongside everything else), visit
   `http://localhost:3000/games/snake` and click **Play**.

`unity/*/Build/` is gitignored — builds aren't committed, matching
production where they ship to R2 instead.

## Protocol reference

See [`packages/games/src/snake/module.ts`](../../packages/games/src/snake/module.ts)
for the source of truth. Summary:

**Server → client**
- `{ type: "welcome", payload: { playerId, gridSize } }` — once, on join.
- `{ type: "state", payload: { gridSize, food: [{x,y}], snakes: [{id, displayName, segments, alive, score}] } }` — every simulation step (150ms).
- `{ type: "died", payload: { score } }` — once, when your snake dies.

**Client → server**
- `{ type: "input", payload: { direction: "up" | "down" | "left" | "right" } }`
